Gameplay Logic Scripting¶

Battlefield 6 Portal now supports multiple ways to script custom gameplay logic for your Custom Experiences. For veterans of the previous Portal builder tool, and people looking to dip their toes into scripting, the Blockly logic editing tool is still available in the Portal Web Builder Tool. However for more advanced users, and creators looking to build large bespoke experiences, Portal now supports logic scripting via TypeScript.

Gameplay scripting can be done either through the Portal Web Tool via Blockly, or in TypeScript.

  • TypeScript can be written directly within the Portal Web Tool’s script page, or can be developed externally and uploaded via the script page.

  • More information about TypeScript functions can be found in the index.d.ts file contained in the SDK.

Script Debugging¶

Local hosting an experience will generate a PortalLog.txt file that can be used to help debug your scripts.

  • The PortalLog.txt file can be found at: C:\Users\username\AppData\Local\Temp\Battlefield™ 6\PortalLog.txt

  • Note the specific folder location may differ depending on specifics of your system or install location.

Custom UI¶

A fully customizable UI system is now available in Portal. It supports interactive as well as non-interactive UI elements, making it possible to build things like menus and stores.

AI Behavior¶

Custom AI Bots, outside of the normal Backfill or Static bots, can be directly spawned into levels via script, using the AI_Spawner object. Unlike normal bots, the Custom AI Bots support direct scripting of things like their target, stance, speed, move to location, etc. This allows for a great deal of customization and flexibility.

Object Spawning¶

Environmental and Gameplay objects can be spawned at runtime via the SpawnObject function. Spawnable objects are restricted by map to objects that already exist in that map or are part of the Global object list.

VFX Spawning¶

Visual FX can be spawned using the runtime spawner, or placed in the map using the Spatial editor, and can be triggered at runtime via the EnableVFX function.

Audio¶

SFX Triggering¶

SFX can be spawned using the runtime spawner, or placed in the map using the Spatial editor, and can be triggered at runtime via the PlaySound function.

Just like with other objects, SFX can be moved at runtime via the MoveObject, MoveObjectOverTime, SetObjectTransform, or other related functions.

Music System Summary¶

Music packages must first be loaded using the LoadMusic function, where you load in a whole music package, such as loading in all Battle Royale music:

mod.LoadMusic(mod.MusicPackages.BR)

It is advised to do this as early as possible to allow a few seconds of time for the music to load in. Typically, you’d load it in during OnGameModeStarted. Next, you can trigger any music event that’s part of the loaded music packages, using PlayMusic. Stopping music is an event in and of itself, such as mod.PlayMusic(mod.MusicEvents.BR_Stop). The way a music package is laid out, is that certain music events are designed to seamlessly transition into the next event. You do not need to stop an event before playing another event in the same package.

Example:

export async function OnGameModeStarted() {
    mod.LoadMusic(mod.MusicPackages.Core);
    mod.SetMusicParam(mod.MusicParams.Core_Amplitude, 1.3);
}

function SomeFunctionInYourExperience() {
    mod.SetMusicParam(mod.MusicParams.Core_IsWinning, 1, winningTeam);
    mod.SetMusicParam(mod.MusicParams.Core_IsWinning, 0, losingTeam);
    mod.PlayMusic(mod.MusicEvents.Core_EndOfRound_Loop);
}

// winningTeam and losingTeam are not readily available variables.
// You will need your own way of passing in the correct teams.

Music Packages¶

The MusicPackages enum is used as an argument for LoadMusic and UnloadMusic.

The enum values are as follows:

  • mod.MusicPackages.Core: Core multiplayer gamemodes, such as conquest and breakthrough.

  • mod.MusicPackages.BR: Battle Royale.

  • mod.MusicPackages.Gauntlet: Gauntlet.

  • mod.MusicPackages.Radio: Music tracks that are typically found in the in-game radios.

Music Events¶

This enum is used as an argument for mod.PlayMusic(). The enum values are as follows:

  • mod.MusicEvents.Core_Deploy_Loop: Quiet and ambient looping track, played when being deployed.

  • mod.MusicEvents.Core_PhaseBegin: One-shot track. Controlled by the following states (via mod.SetMusicParam()):

    • mod.MusicParams.Core_IsWinning: Different track for winning 1 and losing 0.

    • mod.MusicParams.Core_Sector: Different track for non-sector gamemodes 0 and sector gamemodes 1, 2, and 3 (unique music for each sector).

  • mod.MusicEvents.Core_PhaseEnded: One-shot music track. Controlled by the following states (via mod.SetMusicParam()):

    • mod.MusicParams.Core_IsWinning: Different track for winning 1 and losing 0.

    • mod.MusicParams.Core_Sector: Different track for non-sector gamemodes 0 and sector gamemodes 1, 2, and 3 (unique music for each sector).

  • mod.MusicEvents.Core_LastPhaseBegin: One-shot track.

  • mod.MusicEvents.Core_Overtime_Loop: Quiet and suspenseful looping track used when in overtime (e.g. capturing a point on Breakthrough in overtime).

  • mod.MusicEvents.Core_EndOfRound_Loop: Played at the end of a match. Controlled by the following states (via mod.SetMusicParam()):

    • mod.MusicParams.Core_IsWinning: Different track for winning 1 and losing 0.

    • mod.MusicParams.Core_Sector: Different track for non-sector gamemodes 0 and sector gamemodes 1, 2, and 3 (same music for all three sectors).

  • mod.MusicEvents.Core_Stinger_RankUp: Stinger played at the end of a match when you rank up.

  • mod.MusicEvents.Core_Stinger_Positive: A stinger that is played mid-match.

  • mod.MusicEvents.Core_Stinger_Negative: A stinger that is played mid-match.

  • mod.MusicEvents.Core_PauseMenu_Loop: Quiet and ambient looping track. In core gamemodes, this plays in the pause menu only when there isn’t some other higher-priority music track being played, such as Core_PhaseEnded.

  • mod.MusicEvents.Core_Stop: Stops any events playing in the core music package.

  • mod.MusicEvents.BRGauntlet_WaitingForPlayers_Loop: Quiet looping track, played while waiting for players in the lobby. This is a shared event between BR and Gauntlet.

  • mod.MusicEvents.BRGauntlet_LobbyFilled: Played when lobby is filled. Prior to executing this, you may need to set the timer with mod.SetMusicParam(mod.MusicParams.BRGauntlet_LobbyTimerRemaining, 10), using any value from 10 down to 0. This parameter only needs to be set once, and does not need to be updated with an actual timer.

  • mod.MusicEvents.BR_InsertionCinematic_Loop: A one-shot that then automatically transitions into BR_InsertionCinematic_Dropzone_Loop after a few seconds, thus becoming a loop.

  • mod.MusicEvents.BR_InsertionCinematic_Dropzone_Loop: A loop that is automatically transitioned into from BR_InsertionCinematic_Loop. However, this can be triggered to transition into the dropzone music earlier.

  • mod.MusicEvents.BR_InsertionJump: One-shot track.

  • mod.MusicEvents.BR_InsertionLanding: One-shot track.

  • mod.MusicEvents.BR_RespawnTower: One-shot track.

  • mod.MusicEvents.BR_RespawnSecondChance: One-shot track.

  • mod.MusicEvents.BR_LastTwoSquads: One-shot track. Played when you are in the last two squads remaining.

  • mod.MusicEvents.BR_Loss_Early_Loop: Looping track. Played when you get eliminated before the end of the round.

  • mod.MusicEvents.BR_Loss_EndOfRound_Loop: Looping track. Played when you lost at the end of the round while in third place or worse.

  • mod.MusicEvents.BR_Loss_SecondPlace_Loop: Looping track. Played when you finish a round and come in second place.

  • mod.MusicEvents.BR_WonRound_Loop: Looping track. Played when you win a round.

  • mod.MusicEvents.BR_Pause: Pauses whatever BR music is currently playing.

  • mod.MusicEvents.BR_Unpause: Unpauses BR music.

  • mod.MusicEvents.BR_Stop: Stops any events playing in the BR music package.

  • mod.MusicEvents.Gauntlet_Deploy: One-shot track.

  • mod.MusicEvents.Gauntlet_MissionBriefing_One: One-shot track.

  • mod.MusicEvents.Gauntlet_MissionBriefing_Two: One-shot track.

  • mod.MusicEvents.Gauntlet_MissionBriefing_Three: One-shot track.

  • mod.MusicEvents.Gauntlet_MissionBriefing_Final: One-shot track.

  • mod.MusicEvents.Gauntlet_Urgency: Long one-shot track, 35s long.

  • mod.MusicEvents.Gauntlet_Urgency_FinalMission: Long one-shot track, 35s long.

  • mod.MusicEvents.Gauntlet_Qualified_Loop: Looping track. Transitions smoothly to Gauntlet_Qualified_Outro if triggered subsequently.

  • mod.MusicEvents.Gauntlet_Qualified_Outro: One-shot track. Transitions smoothly from Gauntlet_Qualified_Loop if triggered subsequently, but can also be triggered as a standalone.

  • mod.MusicEvents.Gauntlet_WonOperation_Loop: Looping track.

  • mod.MusicEvents.Gauntlet_Loss_Loop: Looping track. Played when losing on any mission other than the final one.

  • mod.MusicEvents.Gauntlet_Loss_FinalMission_Loop: Looping track.

  • mod.MusicEvents.Gauntlet_Pause: Pauses whatever Gauntlet music is currently playing.

  • mod.MusicEvents.Gauntlet_Unpause: Unpauses Gauntlet music.

  • mod.MusicEvents.Gauntlet_Stop: Stops any events playing in the Gauntlet music package.

  • mod.MusicEvents.Radio_Play: Starts playing the queued tracks in the currently selected station. If the queue is empty, nothing will play. Controlled by the following states (via mod.SetMusicParam()):

    • mod.MusicParams.Radio_Channel: You must select one channel and queue up tracks within it. Channels are listed in the MusicParams section.

    • mod.MusicParams.Radio_Biome: If you choose the biome channel (mod.SetMusicParam(mod.MusicParams.Radio_Channel, 4)), you have several biomes to choose from, detailed in the MusicParams section.

    • mod.MusicParams.Radio_QueueTrackNumber: You must queue which songs you’d like to hear. Number of available tracks is detailed in the MusicParams section.

  • mod.MusicEvents.Radio_Stop: Stops playing the queued track. Playing again will restart the same song from the beginning (i.e. this is not a pause function).

  • mod.MusicEvents.Radio_NextQueuedTrack: Skips to the next track in the queue. What will happen at the end of your queue depends on the following two parameters:

    • mod.MusicParams.Radio_ContinueQueueOnTrackEnd

    • mod.MusicParams.Radio_LoopQueuedTracks

  • mod.MusicEvents.Radio_ClearQueue: Clears the queue of tracks. This is the only way to do so. Note, playing a track does not clear it out of the queue, as you may want to loop your queued tracks.

MusicParams¶

The MusicParams enum is used as an argument for SetMusicParam, which is then followed by a second argument of type Number, which represents the value of the parameter. For example: mod.SetMusicParam(mod.MusicParams.Core_IsWinning, 1). This ensures that all core music will play their “winning” variants, if they have one.

  • mod.MusicParams.Core_Sector: Some music events in the core music package have different variations based on what sector you are in, including a variant for game modes that do not use sectors at all. Set the value to 0 to imply a gamemode that does not use sectors (e.g. Conquest), or use values 1, 2, or 3 to play music for those respective sectors for a gamemode that does use sectors (e.g. Breakthrough). Numbers are clamped to a range between 0 and 3, and decimals are rounded to the nearest integer.

  • mod.MusicParams.Core_Urgency: This functions like a music event. It is a looping track played when nearing the end of a round. As soon as the value goes above zero, urgency music starts playing. Numbers are clamped to a range between 0 and 4. Each whole number represents one layer of music that plays on full volume, while the decimals between them act as a crossfade. For example, if you set the value to 2.5, it plays both layer 2 and layer 3 each at partial volume.

  • mod.MusicParams.Core_PhaseUrgency: This functions like a looping music event. Same as Core_Urgency, but it only goes from 0 to 3, and is used when nearing the end of a phase, rather than the end of a round.

  • mod.MusicParams.Core_IsWinning: Many core music events have a winning and losing variant, which is controlled by this parameter. This is effectively a boolean, but this value actually takes in a number 0 or 1.

  • mod.MusicParams.Core_Amplitude: Loudness of core music events, represented as a multiplier. 0 is silent, 1 is the full default volume. This parameter is clamped from 0 to 3, so if you wanted, you can play the music at triple volume. Please be mindful of not blasting people’s ears out.

  • mod.MusicParams.BRGauntlet_LobbyTimerRemaining: Shared parameter for both the BR and Gauntlet music packages. When the lobby fills up in both BR and Gauntlet, it starts a timer from 10 to 0. You only need to set this timer once before executing mod.PlayMusic(mod.MusicEvents.BRGauntlet_LobbyFilled), and you do not need to simulate an actual countdown timer for this parameter.

  • mod.MusicParams.BR_Amplitude: Loudness of BR music events, represented as a multiplier. 0 is silent, 1 is the full default volume. This parameter is clamped from 0 to 3, so if you wanted, you can play the music at triple volume. Please be mindful of not blasting people’s ears out.

  • mod.MusicParams.Gauntlet_Amplitude: Loudness of Gauntlet music events, represented as a multiplier. 0 is silent, 1 is the full default volume. This parameter is clamped from 0 to 3, so if you wanted, you can play the music at triple volume. Please be mindful of not blasting people’s ears out.

  • mod.MusicParams.Radio_Channel: Sets the channel from which you will be queueing tracks. There may be tracks whose genres don’t fit the labels below. You have access to the following channels (the BF Pro channel is not available through the Portal music system):

    • 0: Hip Hop

    • 1: Rock

    • 2: BF Themes

    • 3: Reggaeton

    • 4: Biome-specific (selected via Radio_Biome)

    • 5: Classical

    • 6: Pop

  • mod.MusicParams.Radio_Biome: If set to channel 4, this is used to select which biome’s radio station to queue tracks from. The tracks may not necessarily be from the country or region listed in the biome name, but rather are simply the tracks you hear in radios in maps set in these biomes. You have access to the following biomes:

    • 0: Gibraltar

    • 1: Tajikistan

    • 2: Egypt

    • 3: US - West Coast

    • 4: US - East Coast

    • 5: Bulgaria

    • 6: Turkmenistan

  • mod.MusicParams.QueueTrackNumber: Select which track to add next in the queue. The queue is empty by default, and no track will play until you queue up tracks. Here are the track lengths of each station as of Season 3 (a station that has 17 tracks are indexed 0 through 16):

    • Channel 0: 17 tracks

    • Channel 1: 18 tracks

    • Channel 2: 10 tracks

    • Channel 3: 2 tracks

    • Channel 4: Biome-specific:

      • Biome 0: 18 tracks

      • Biome 1: 16 tracks

      • Biome 2: 16 tracks

      • Biome 3: 19 tracks

      • Biome 4: 18 tracks

      • Biome 5: 2 tracks

      • Biome 6: 18 tracks

    • Channel 5: 32 tracks

    • Channel 6: 15 tracks

  • mod.MusicParams.Radio_ContinueQueueOnTrackEnd: If 1, when the current song is done, the next queued song will start. If 0, the radio will auto-stop. Playing the radio again after a song ends will play the next queued song.

  • mod.MusicParams.Radio_LoopQueuedTracks: If 1, when the last queued song is done, the song at the start of the queue will start. If 0, the radio will auto-stop. Playing the radio again after a queued list ends will go back and play the first queued song.

  • mod.MusicParams.Radio_Amplitude: Loudness of Radio music events, represented as a multiplier. 0 is silent, 1 is the full default volume. This parameter is clamped from 0 to 3, so if you wanted, you can play the music at triple volume. Please be mindful of not blasting people’s ears out.

Objects can be moved at runtime via the MoveObject function or the SetObjectTransform.

Referencing Objects In Script¶

Most objects placed in the Spatial Editor have an ObjId field which can be set to a unique number. These objects can be referenced in script by using a matching “Get” function like:

  • GetSpatialObject

  • GetSpawner

  • GetInteractPoint

Using strings.json

  • String files can be manually crafted using key/value pairs in json format. Such strings can be used either via their keys or their values from script.

  • String files can also be auto generated from the web editor after importing the script. It will scrub code for string literals (“Cool Scoreboard Title”) but will not pick up dynamically constructed strings (i.e. “player “ + i + “ kill count: “ + count)

  • Example:

// strings.json
{
  "scoreboard": "Custom Scoreboard",
}

// script.ts
const msg1 = mod.Message(mod.stringkeys.scoreboard);
const msg2 = mod.Message("scoreboard");
const msg3 = mod.Message("Custom Scoreboard");

// String literals require generating strings json from web editor
// if not defined in strings.json
const playerRank = "Player Rank";
const rankMsg = mod.Message(playerRank);
